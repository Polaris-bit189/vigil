# 时间注入：让界面知道「现在」

> 方向：把「当前时间」注入到更多地方。
> **不需要新模块** —— 但要改一处**前端已有的时间函数**。
>
> ✅ **本文档 §二、§三 已于 2026-10-15 落地**（后端 866 / 前端 263 全绿）：
> `web/src/format.ts::relDeadline`、`vigil/deadline.py::deadline_level`、
> `vigil/digest.py::_weekday_suffix` 与「别忘」的倒计时。
> 日历侧也已接上（`Calendar.tsx::DeadlineHeading`）。

## 一、现状：已做的 vs 缺的

### ✅ 已做：模型知道「今天」

`refine.build_user_prompt`（`vigil/refine.py:170`）的提示词首句就是：

```
今天的日期是 {today}。
```

源码注释记着为什么（`refine.py` 的 docstring）：

> 不告诉模型「今天」是哪天，它会把「9月7号」猜成**过去的年份**
> （探针实测：猜成了 **2023**）。

**这一条已经在跑，不用动。**

### ⚠️ 缺的：界面不知道「现在」

前端 `web/src/format.ts` 只有四个时间函数，其中：

```ts
export function relTime(ts: number): string {
  const diff = Date.now() / 1000 - ts
  if (diff < 0) return fmtDate(ts)   // ← ⚠️ 这一行是关键
  ...
}
```

**`diff < 0`（未来时间）直接回退成绝对日期。** 而
**死线永远在未来** —— 所以：

| 场景 | 现在显示 | 应该显示 |
|---|---|---|
| 死线是明天 | `10月15日` | 🔴 **明天截止** |
| 死线是 3 天后 | `10月17日` | 🟠 还有 3 天 |
| 死线已过 | `10月10日` | ⬜ 已过期 |

⚠️ 这不是 bug（`relTime` 的定位就是"过去发生的事"），
而是**缺一个函数** —— `relTime` 没打算处理未来。

## 二、要加的：`relDeadline()`

```ts
/** 距死线还有多久。与 relTime 相反 —— 它算的是**未来**。 */
export function relDeadline(deadlineTs: number): {
  text: string;      // "今天" / "明天" / "还有 3 天" / "已过期 2 天"
  level: 'urgent' | 'soon' | 'normal' | 'expired';
}
```

**分级规则**（与 `日程表.md` 阶段 3 共用一套，两处不许各写一份）：

| 距今天数 | level | 文案 |
|---|---|---|
| < 0 | `expired` | 已过期 N 天 |
| 0 | `urgent` | **今天截止** |
| 1 | `urgent` | 明天截止 |
| 2–3 | `soon` | 还有 N 天 |
| 4–7 | `normal` | 还有 N 天 |
| > 7 | `normal` | 绝对日期 |

⚠️ **分级必须两边共用**：日历用它排色，日报用它排文案。
两处各写一份阈值（一处 `<=1` 一处 `<2`）是这类功能最经典的漂移 ——
而症状是"日历上标红了、日报里没提"，查起来毫无头绪。

**落地方式**：写在前端（`format.ts`），**日报那侧由后端算** ——
因为日报是 Markdown 文本，生成时就固定了，不能靠前端算。

⚠️ 这意味着**分级规则要在 TS 与 Python 各存在一份**。
这是个**真实的取舍**，不是疏忽：
- 日报要落盘成 `.md`（后端渲染），前端拿不到
- 日历要跟随"当前时刻"变化（前端渲染），后端算完会过期

**做法**：两份都写，**并在各自的注释里互相指路**
（`format.ts` 指向 `deadline.py`，反之亦然），
再在测试里各钉一条同样的边界用例（0 天 / 1 天 / 8 天）。

## 三、日报标题加星期

现在日报文件名是 `2026-10-14.md`，正文首行是日期。
**建议加上星期**：

```
2026年10月14日 · 星期二
```

⚠️ 为什么值得做（不是装饰）：
「**周三截止**」这种写法在群消息里**到处都是**。加了星期，
用户看到死线时能**一眼对上**群里的说法，不必在脑子里做换算。

**实现注意**：Python 的 `datetime.strftime("%A")` 在无 locale 的环境下
**返回英文**（`Wednesday`）。要用 `calendar` 模块的中文映射，
**或者**（更稳）自己查表：

```python
_WEEKDAY_CN = ("一", "二", "三", "四", "五", "六", "日")
f"星期{_WEEKDAY_CN[d.weekday()]}"
```

⚠️ 别用 `strftime("%A")` + `locale.setlocale` —— 改 locale 是**全局副作用**，
而服务是多线程的（`api.py` 的模块 docstring 提到端点跑在线程池里）。
