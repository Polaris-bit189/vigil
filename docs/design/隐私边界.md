# 隐私边界

> VIGIL 的合规论证与**它的边界**。本文档刻意把「拦得住什么」与
> 「拦不住什么」分开写 —— 只讲前者是营销，不是工程文档。

---

## 一、风险在哪

VIGIL 读的是**别人的消息**。两个动作有合规含义：

| 动作 | 风险 | 处置 |
|---|---|---|
| **读取**（本机 QQ 库） | 读自己的数据，法理上最轻 | 保留 |
| **传输**（发给云端 LLM） | 「向第三方提供个人信息」——**整条链路上风险最高** | **移除** |

采纳的架构把「传输」从链路上拿掉：敏感数据在本机用本地模型完成抽取，
只有脱敏后的结构化结果离开这台机器。

```
本机（数据不出网）：QQ库 → export → messages → refine（本地模型）→ items（脱敏）
                                                                      ↓ 只传这个
华为云：RDS / Redis → digest / Web / PWA
```

## 二、三道防线（自上而下）

### 防线 1：输入端不给名字（**根治**）

在 `refine.build_user_prompt` 里，出网的每一段文本都过两道：

```python
body = sanitize_for_llm(redactor.scrub_names(redactor.text(m.content)))
#                       ↑ 抹已知人名        ↑ 抹号码
```

- 称呼（"谁说的"）走 `Redactor.name()` —— **保留角色词与班级前缀、抹掉人名本体**
- 正文（"说了什么"）走 `Redactor.scrub_names()` —— 用 `sender_names` 表里的
  **已知昵称**做精确替换

**为什么用"已知名单精确替换"而不是"正则识别中文姓名"**：
中文姓名没有可靠的字面特征（「明天」也像名字），正则识别会大量误伤正文。
而我们**本来就知道**这个群有哪些人 —— `sender_names` 表里全是。

### 防线 2：号码遮蔽（四层）

`Redactor.text()` / `redact_text()` 挡四类东西：

1. **URL 段整体豁免** —— 链接里的文档 ID 是结构化标识符，抹掉会把链接打烂
2. **手机号** —— 11 位，两侧带数字边界（缺边界会留 `90` 残渣）
3. **长数字串 ≥10 位** —— 学号、订单号
4. **身份标签后的短数字** —— `QQ`/`群号`/`群` 等标签后接 5–12 位

### 防线 3：机械判据（**可证伪**）

隐私边界不是口头承诺。测试里有一条：

```python
def test_prompt_contains_no_real_name():
    NAMES = {"张三", "李四", "王五", "赵六"}
    # 构造带这些名字的消息（**正文里也点名**）
    ...
    assert not [n for n in NAMES if n in text], "姓名出网了"
```

它同时压两条路径：**称呼**（`name()`）与**正文**（`scrub_names()`）。
第一版只改了称呼，这条判据一跑，四个夹具姓名**全部**泄漏 —— 于是补上了第二道。

## 三、⚠️ 拦不住什么（如实记）

**模型凭空造出一个不在名单里的人名，防线 1 拦不住。**

理由：`scrub_names` 是**精确子串替换**，它只能抹掉**名单上有**的名字。
模型若从别处"补出"一个名字，那张名单里没有它。

**缓解**：输入端不给名字（防线 1 的根治性）—— 模型拿不到真名，
它"补"出来的也只可能是训练语料里的常见姓名，而不是本群这个人。

**为什么不用"中文姓名正则"兜底**：误伤率不可接受。中文里
「明天」「高兴」「主任」都符合"2 字汉字"的形状，一条宽松的正则会把
正文咬得面目全非 —— 而**打坏正文的代价是确定的**（抽取质量直接下降），
收益是不确定的（它未必真在挡什么）。

**这条边界的诚实记法**：材料里应写「出网文本不含**已知名单**里的姓名」，
而不是「出网文本不含任何姓名」。后者是一句我们**证明不了**的话。

## 四、云侧：传什么、不传什么

`vigil/sync.py` 的隐私契约（它是那个模块存在的全部理由）：

| 表 | 传吗 | 为什么 |
|---|---|---|
| `items` | ✅ | `title`/`detail` 已过防线 1 |
| `digests` | ✅ | 由 items 合成，同样已脱敏 |
| `sender_names` | ❌ | **全库唯一含真实姓名的表** |
| `messages` | ❌ | 含原文，违背"原文不出本机" |
| `msg_media` | ❌ | 同上 |
| `items.actor_uid` | ⚠️ **置空后传** | 跨机器稳定标识符，虽不含姓名但仍指得到人 |

## 五、Demo 与真实数据的关系（必须在材料里讲清）

云端 Demo 演示的是**同一套代码 + 合成数据**；真实数据流在**本机**。

⚠️ **这个结构必须主动讲**，否则会被评委当成"演示与真实效果不符" ——
而那正对应赛题第⑦条（复现不符即取消资格）。

正确说法：**代码是同一份，数据是合成的**。评委可以自己
`git clone` → `vigil demo` → 得到与线上完全一致的效果
（合成语料是确定性的，同一 seed 产出逐字节相同的库）。
