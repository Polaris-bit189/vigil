# VIGIL · 守夜人

> **V**igilant **I**nformation **G**athering & **I**nsight **L**ayer
> 守望式信息聚合与洞察层

**面向隐私敏感场景的本地 AI 预处理架构** —— 以校园群聊为首个落地场景。

---

## 一句话

群聊里散着通知、学业、活动、二手、失物……每天手动翻太累，
**而漏掉一条可能是几万块的奖学金**。VIGIL 替你值夜班：
敏感数据在**本机**用本地模型完成 AI 抽取，只有脱敏后的结构化结果离开这台机器。

```
    23:47  你在写作业
    00:12  群里发了一条「国家奖学金材料周三截止」
    01:30  VIGIL 读到它，判成「通知公告」，算出死线
    07:58  你起床，日报第一行就是它
```

## 三十秒跑起来

```bash
git clone <本仓库> && cd <本仓库>

# ① 用合成语料建库（离线、不需密钥、不需 QQ）
python -m vigil demo

# ② 抽取结构化条目 —— 需要 LLM 端点。默认配置指向本地 Ollama：
#        ollama pull qwen3:8b
python -m vigil refine

# ③ 起服务，浏览器打开 http://127.0.0.1:8787
python -m vigil serve --host 127.0.0.1 --port 8787
```

**没有第 0 步。** 第 ① 步在任何装了 Python 3.11+ 的机器上都能跑通 ——
合成语料是这份仓库的一部分（`demo/vigil-demo.db`），不需要你提供任何私人数据。

**只想看数据链路、没有模型？** 跑完 ① 之后跳过 ②，用
`python -m vigil groups` 看群清单、`python -m vigil read` 读消息 ——
这些不调模型。⚠️ 但 ③ 的网页要看 `items`，必须先跑过 ②。

> **`vigil demo` 刚才验证过**（2026-10-15，Windows 11 + Python 3.14.7）：
> 1237 条消息、4 个群，退出码 0。① → ② → ③ 全链路实跑通过。
> ② 用本地 `qwen3:8b` 抽 60 条消息产出 22 条条目。

> **换端点**：`config/llm.toml` 里改 `base_url` / `model` / `auth`。
> 本地 Ollama 用 `auth = "none"`（它不接受空的 `Bearer ` 头）；
> 华为云 MaaS 用 `auth = "bearer"` + `api_key_env` 指向你的密钥变量。
> 改完不用重启服务 —— 每次运行都会重新读它。
>
> 用 `uv` 更快（本仓库带 `uv.lock`）：
> ```bash
> uv sync && uv run vigil demo && uv run vigil refine && uv run vigil serve
> ```

### ⚠️ Windows 上的两个坑（实测踩到，已修）

**① 中文 Windows 的控制台是 GBK**，而输出里有 `✓` `⚠` `⏰` 这类 GBK
编不出来的符号。**已修**（`cli._harden_streams` 把编码错误处理改成
`replace`，中文照常显示、稀有符号降级成 `?`，不再中断）。
若你用**旧版本**遇到 `UnicodeEncodeError: 'gbk' codec can't encode...`
（症状：`vigil demo` 建到一半崩、库里消息不全），临时解法：

```bash
set PYTHONUTF8=1     # cmd
export PYTHONUTF8=1  # bash
```

**② 端口可能落在 Windows 保留段**，报
`[WinError 10013] 以一种访问权限不允许的方式做了一个访问套接字的尝试`。
实测本机 **8787 与 8899 都在保留段里**（`netsh int ipv4 show excludedportrange
protocol=tcp` 可查；保留段来自 Hyper-V / Docker / WSL）。换一个端口即可：

```bash
python -m vigil serve --port 18888
```

⚠️ 这不是 VIGIL 的缺陷 —— 是 Windows 把那段端口留给了别的服务。
**遇到 10013 不要怀疑代码，先换端口。**

## 为什么是"本地预处理"

群聊里是**别人的消息**。把它们发给云端 LLM，是整条链路上合规风险最高的动作 ——
**"向第三方提供个人信息"**。VIGIL 把这个动作从链路上移除：

```
┌─ 本机（私有，数据不出网）──────────────────┐
│  QQ 本地库 → export → messages             │
│                  ↓                         │
│            refine ← 本地模型（Ollama）      │
│                  ↓                         │
│            items（结构化 + 强脱敏）         │
└──────────────────┬─────────────────────────┘
                   │  只上传结构化结果
┌──────────────────▼─────────────────────────┐
│  华为云：ECS / RDS / DCS                    │
│  digest（日报合成） / Web / PWA             │
└────────────────────────────────────────────┘
```

**隐私边界不是口头承诺，是可证伪的机械断言**：测试里有一条
`test_prompt_contains_no_real_name` —— 构造一批带真实姓名的消息，
断言**发给模型的提示词里一个姓名都不出现**（`tests/test_refine.py`）。

## 它能做什么

| | 一句话 |
|---|---|
| **一页看完** | 每天一份日报：通知 / 学业 / 活动 / 生活 分好类，按死线排好序 |
| **不再漏** | 自动抽取时间与地点；`deadline` 与事件时序有**机器闸门**把关（编造的死线进不来） |
| **知道急不急** | 死线带倒计时：「今天截止 / 明天截止 / 还有 N 天」，日报标题带**星期**——群里写「周三截止」时能一眼对上 |
| **点开看地点** | 有地点的条目可以「在地图中查看」（实测覆盖 32%；**是搜索不是导航**，见下） |
| **按人看** | 想知道某个同学 / 班委发过什么？`config/persons.toml` 录一个 uin，网页上一点就筛出来 |
| **随手纠** | 界面里改分类、软删、撤销 —— 都记在**人工干预层**，`refine` 与日报**两处**都认 |
| **随处看** | 手机装成 PWA，锁屏上一眼扫完 |
| **几套皮** | 默认 / Material / 粗野主义 / 蒸汽波 / 毛玻璃，外加一个彩蛋（见下） |

### ⚠️ 「在地图中查看」是**搜索**，不是导航

条目自动抽取地点（实测覆盖率 **32%**，120/375），并可一键在公开地图里搜。

**但它做不了室内导航** —— 校园内部建筑（「实验楼 305」「食堂二楼」）在
高德/百度上**没有独立点位**，搜出来只会是学校大门。所以按钮文案刻意是
「**在地图中查看**」而不是「导航」：叫导航会让用户点了发现到的是校门，
以为是 bug。

⚠️ 这两个数（32% / 真正可导航 29.6%）都如实写在
`docs/design/地点导航.md`：只说「32% 有地点」会被理解成「都能导航」，
而评委复现时会发现「老地方」点开是个空搜索页。

### 防幻觉是**设计**出来的，不是祈祷出来的

LLM 会编。实测过：源文只写「明早 7:20 集合」，模型照样填了一个具体日期 ——
而日报会把这个幻觉**洗成机器权威**。所以死线要过两道闸：

1. **`deadline_supported`** —— 这个日期**能不能在源消息正文里逐字找到**。
   找不到就是编的，降级。
2. **`deadline_sane`** —— 找得到，但**早于消息时间**（已过期三个月），也降级。

两道闸分开关，因为运维含义不同。**只认带月份的写法**——「26号」这种裸日不算依据
（实测精度 0/2：源文「我有一个朋友26号就开学」被拿去给一个 09-26 的截止日背书）。

详见 `vigil/deadline.py` 的 docstring，那里记着每一条判据的实测来历。

## 🜂 彩蛋：Project ARGUS

主题切换里有第六个选项。它不叫名字，**而是一段乱码** —— 几秒之后才显出真名。

选中它，整个界面变成一台终端：纯黑底、等宽字、`ARGUS:~$` 提示符。
左上角是它的徽记与大号 **ARGUS**：

> **睡亦警觉，眼观六路**

在提示符后敲 `/color green`（或任意 hex），整套界面的颜色跟着变。
太暗的颜色会被拒（在纯黑底上读不出来，它会直说）。

## 架构

```
vigil/
  source.py      数据源抽象（Source 协议）——换数据源不必改下游
  synth.py       合成语料生成器（可复现、确定性）
  web_source.py  网页通知源（只读公开页面，零新增依赖）
  ingest.py      把源的消息落成 tables（下游唯一契约）
  prefilter.py   粗筛（哪些消息值得送模型）
  redact.py      脱敏（号码四层遮蔽 + 出网姓名遮蔽）
  refine.py      LLM 结构化抽取
  deadline.py    死线机器闸门（防幻觉核心）
  digest.py      日报合成
  store.py       六张表 + FTS5
  api.py         只读 JSON API
  overrides.py   人工干预层（append-only 事件表）
web/             React 19 + Vite + Tailwind + PWA
```

### 两条不变量

- **Web 侧绝不写 `data/vigil.db`**：连接一律 `mode=ro` 打开，写操作被 SQLite
  直接拒绝。这条是机械保证 —— 测试里逐字节比对主库指纹。
- **删除是软的**：界面上消失，库里的行仍在，而且**不会被重抽复活**。

## 边界（明确不做）

多用户 / 权限、跨机器合并、已删条目的物理清理、图片 OCR、富消息段解析。

- **数据源**：本仓库自带**两条**完整可跑的路 ——
  · **合成语料**（默认，`source = "synthetic"`）：离线、确定性、评测用。
  · **网页通知源**（`source = "web"`）：只读**公开发布**的校园通知页。
    零新增依赖（标准库），配 `config/sources.toml` 加源。
    ⚠️ 抓取产物会落盘成夹具（`demo/sources-fixture.json`），
    **演示与复现从夹具读、不联网** —— 否则站点改版/评委不在校内网
    都会让复现失败。
  · **本机 QQ 加密库**：需要私有模块 `vigil/qq_source.py`，**不随本仓库分发**
    —— 本仓库的默认安装**不含任何解密库**（`pip install .` 不会拉 `sqlcipher3`）。
    ⚠️ 那条路读的是群聊原文，**不做实时抓取也不公开分发**（见 `docs/` 的合规论证）。
- **云部署**：见 `docs/design/云端部署.md`。
